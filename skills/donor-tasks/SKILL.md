Manage donor-related tasks (thank-you calls, follow-ups, challenges) in the Donor
Management DB.

## Invocation Triggers

**Explicit:** "show my donor tasks," "thank-you tasks," "what donor follow-ups do I have?," "complete that donor task."

**Create:** "create a task to call [name]," "remind me to thank [name]," "add a follow-up task."

## How Donor Tasks Work

The **Donor Management DB is the source of truth.** Tasks are auto-generated by rules
and can be manually created.

Historically a second copy was mirrored into todo-api so donor tasks appeared alongside
other next actions. That mirror is retiring with todo-api and has no Vikunja equivalent
yet (**C2** in the cutover runbook), so donor tasks currently live in the donor system
only and are surfaced by this skill and by the morning briefing's donor step — not by the
`vikunja-*` task skills.

**Auto-generation rules** (via `auto_tasks.py` in the donor DB):
- **First gift** → thank-you task created automatically
- **Returning donor** (18+ month gap between gifts) → thank-you task
- **Large gift** (>1.5x the donor's average) → thank-you task

## Querying Donor Tasks

### From the Donor Management DB (direct)

```
GET https://donor-management.fly.dev/api/v1/tasks?status=pending
Header: X-API-Key: [from TOOLS.md]
```

Filter options:
- `?status=pending` — incomplete tasks
- `?status=completed` — finished tasks
- `?contact_id=N` — tasks for a specific donor

### Single Task Detail

```
GET https://donor-management.fly.dev/api/v1/tasks/{id}
Header: X-API-Key: [from TOOLS.md]
```

### Task Types

```
GET https://donor-management.fly.dev/api/v1/tasks/types
Header: X-API-Key: [from TOOLS.md]
```

Returns available types: Thank, Call, Letter, Visit, Follow-Up, etc.

### Cross-system view — RETIRING, do not use

`GET /donor-tasks` and `GET /donor-tasks/{id}` on `gtd-api.fly.dev` showed donor tasks
mapped into the old task system. Those endpoints go read-only at the cutover and have no
replacement. Use the donor API queries above.

## Completing Donor Tasks

```
POST https://donor-management.fly.dev/api/v1/tasks/{id}/complete
Header: X-API-Key: [from TOOLS.md]
```

This is the route, not a fallback. The old `PATCH /donor-tasks/{id}/status` on
`gtd-api.fly.dev` — which used to be preferred because it completed the task in the task
system *and* pushed the completion back here — is retiring with todo-api. Completing in
the donor system is now the only place a completion needs to happen, because there is no
second copy to keep in step.

### After Completing

Suggest logging the interaction: "Want me to log this call/visit in the donor history too?" (Use the `donor-log` skill.)

## Creating Tasks Manually

```
POST https://donor-management.fly.dev/api/v1/tasks
Header: X-API-Key: [from TOOLS.md]
Body: {
  "task_type_id": 1,
  "description": "Call to thank for first gift of $100",
  "task_date": "2026-03-02",
  "status": "pending",
  "is_thank": true,
  "contact_ids": [42]
}
```

**Fields:**
- `task_type_id` (required) — from `/tasks/types`
- `description` — what needs to be done
- `task_date` — when the task should be done (ISO date)
- `status` — `pending` (default) or `completed`
- `is_thank` — `true` if this is a stewardship/thank-you task
- `contact_ids` (required) — array of related contact IDs


(The old `PATCH /donor-tasks/{id}/status` with `{"status": "deleted"}` on
`gtd-api.fly.dev` did the same thing through the task system. Retiring — see the banner
at the top.)

## API Reference

**Donor Management DB** — Endpoint and credentials in `/workspace/TOOLS.md`.
Base URL: `https://donor-management.fly.dev`

```
GET    /api/v1/tasks              — list tasks (?status=, ?contact_id=)
GET    /api/v1/tasks/{id}         — task detail

PUT    /api/v1/tasks/{id}         — update task
DELETE /api/v1/tasks/{id}         — delete task
GET    /api/v1/tasks/types        — list task types
POST   /api/v1/tasks/{id}/complete — complete task
```

**Task system** — none. Donor tasks are not in Vikunja. The three `/donor-tasks`
endpoints on the retired `gtd-api.fly.dev` (`GET /donor-tasks`, `GET /donor-tasks/{id}`,
`PATCH /donor-tasks/{id}/status`) are listed here only so a future session recognises
them as dead rather than as something to reach for. Their replacement is Phase C item
**C2, build the donor → task push against Vikunja**.
